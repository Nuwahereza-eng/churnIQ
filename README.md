# Telco Churn Insight: Customer Churn Prediction

Undergraduate Software Engineering research project:
**Development and Evaluation of a Machine Learning Model for Predicting Customer Churn in the Telecommunications Industry.**

The project trains and compares three classifiers (Logistic Regression, Decision Tree, Random Forest) on the public
IBM Telco Customer Churn dataset, and presents churn patterns and predictions in a web application. There are two
front ends over the same trained model:

- **ChurnIQ** (main app): a React + TypeScript frontend (`frontend/`) talking to a FastAPI backend (`backend/`).
- **Streamlit app** (`app.py`): the original single-process prototype, kept working.

> The dataset describes a **fictional** telecom provider created by IBM. Results do not describe any real company or
> the Ugandan market. Predictions are estimates for decision support, not certainties.

## Results at a glance

Held-out test set of 1,409 customers (20% stratified split, never used for tuning or selection), threshold 0.5:

| Model | CV ROC-AUC (5-fold, train) | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|---|
| Logistic Regression | 0.846 ± 0.013 | 0.739 | 0.505 | 0.783 | 0.614 | 0.841 |
| Decision Tree | 0.833 ± 0.013 | 0.739 | 0.505 | 0.781 | 0.613 | 0.836 |
| Random Forest | 0.848 ± 0.009 | 0.752 | 0.521 | 0.789 | 0.628 | 0.844 |
| Majority-class baseline | – | 0.735 | 0.000 | 0.000 | 0.000 | 0.500 |

**Deployed model:** Random Forest (highest mean CV ROC-AUC), with sigmoid probability calibration and a decision
threshold of 0.36 chosen on training data. On the test set it scores ROC-AUC 0.845, recall 0.714, precision 0.577,
F1 0.638 and accuracy 0.785, with Brier score improving from 0.163 to 0.136 after calibration.
Random Forest and Logistic Regression differ by less than one cross-validation standard deviation, so they should be
regarded as performing similarly.

These numbers come from `reports/evaluation_results.json`, generated by the training script on 2026-10-15. Re-running
training reproduces them (fixed random seed 42); a test checks that the saved model reproduces the stored metrics.

## Installation (Ubuntu)

Requires Python 3.11+ (developed with 3.12). The React frontend also needs Node.js 22.12 or later (developed with
22.15) and npm.

```bash
cd "Customer churn"
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt     # or requirements.txt for the app only
cd frontend && npm ci && cd ..          # frontend dependencies (exact versions from package-lock.json)
```

## 1. Get the dataset

```bash
python scripts/download_data.py
```

This saves `data/raw/Telco-Customer-Churn.csv`. Without internet access, see [data/README.md](data/README.md) for
manual download instructions. The app also offers a **Download dataset** button if the file is missing.

## 2. Explore the data

```bash
jupyter notebook notebooks/exploratory_analysis.ipynb
# or re-run it non-interactively:
jupyter nbconvert --to notebook --execute --inplace notebooks/exploratory_analysis.ipynb
```

## 3. Train and evaluate

```bash
python -m src.train          # about 5 minutes on a 4-core laptop
python scripts/make_figures.py
```

Outputs: `models/churn_pipeline.joblib`, `models/model_metadata.json`, `reports/evaluation_results.json`, and
figures in `reports/figures/`. See [models/README.md](models/README.md) and [reports/README.md](reports/README.md).

## 4. Run the tests

```bash
python -m pytest -q                     # Python: ML code, Streamlit pages and the REST API
cd frontend && npm test                 # Frontend: Vitest + Testing Library
```

The Python suite (97 tests) covers data loading and validation, missing-value handling, preprocessing compatibility and
leakage, unseen categories, model training, prediction format, probability range, batch prediction, invalid input
handling, reproducibility of the saved metrics, and headless rendering of every app page. Training tests use
clearly labelled **synthetic** data (`tests/synthetic.py`); tests that need the real data or model are skipped if
those files are absent. The API tests check every endpoint, including validation errors, upload limits and the
error format.

The frontend suite (23 tests) covers page rendering, sidebar navigation, the not-found page, loading and error states
with retry, prediction-form validation, and batch upload (valid file, invalid rows, wrong file type). It mocks `fetch`
with responses captured from the real API (`frontend/src/test/fixtures/`), so no backend is needed.

## 5. Start the application

### ChurnIQ (React + FastAPI)

Run the backend and frontend in two terminals:

```bash
# Terminal 1: REST API on http://127.0.0.1:8000 (interactive docs at /docs)
source .venv/bin/activate
uvicorn backend.app.main:app --host 127.0.0.1 --port 8000

# Terminal 2: frontend dev server on http://127.0.0.1:5173
cd frontend
npm run dev
```

Open http://127.0.0.1:5173. The dev server forwards `/api` requests to the backend, so no CORS setup is needed.
Use `--reload` on uvicorn while editing backend code.

| Page | Purpose |
|---|---|
| Overview | Headline figures, churn distribution, churn by contract/tenure, charges, latest model run, data-quality checks |
| Customer Explorer | Search, filter, sort and page through the dataset (server-side) |
| Predict Churn | Validated form for one customer → probability, predicted class, risk band, adjustable threshold |
| Batch Predictions | Upload a CSV → validation and preview → scored results, downloadable as CSV |
| Model Performance | Methodology, model comparison, ROC/PR curves, confusion matrices, threshold and calibration charts |
| Insights | Highest/lowest-churn groups, permutation importance, Logistic Regression coefficients, associations |
| About the Research | Purpose, dataset, method, architecture, limitations |

Configuration (environment variables, all optional):

| Variable | Where | Default | Purpose |
|---|---|---|---|
| `CHURNIQ_CORS_ORIGINS` | backend | localhost ports 5173 and 4173 | Comma-separated origins allowed to call the API |
| `VITE_API_BASE_URL` | frontend build | same origin | API URL when it is hosted on a different origin |
| `CHURNIQ_API_TARGET` | frontend dev/preview | `http://127.0.0.1:8000` | Where the dev server forwards `/api` |

For a production build: `cd frontend && npm run build` writes static files to `frontend/dist/`; `npm run preview`
serves them on port 4173 with the same `/api` forwarding.

### Streamlit prototype

streamlit run app.py

## Deployment

**ChurnIQ:** host the FastAPI backend on any Python host (e.g. Render, Railway or a VM:
`uvicorn backend.app.main:app --host 0.0.0.0 --port $PORT`) and the contents of `frontend/dist/` on any static host.
Build the frontend with `VITE_API_BASE_URL` set to the API's URL, and set `CHURNIQ_CORS_ORIGINS` on the backend to
the frontend's URL. The dataset, model and results files must be present on the backend host.

**Streamlit prototype:** it can be deployed to **Streamlit Community Cloud** (free):

1. Push the repository to GitHub, including `models/churn_pipeline.joblib`, `models/model_metadata.json` and
   `reports/evaluation_results.json` (the raw CSV is git-ignored).
2. On share.streamlit.io create an app pointing at `app.py`, and choose Python 3.12 in the advanced settings.
3. On first visit, use the **Download dataset** button (or commit the CSV if your licence review allows).

Any host that can run `streamlit run app.py --server.port $PORT` (e.g. Render, Railway, a VM) also works.
Deployment has not been performed as part of this work.
